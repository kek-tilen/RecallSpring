# 01 — Product Requirements Document (PRD)

## Product thesis

**RecallSpring — Your personal AI learning companion.** Build lasting understanding through a conversational tutor and automatic memory management, without the busywork of maintaining flashcards or review calendars. The app is a new independent product, not a recreation of ChatGPT's proprietary UI. An **English-language Sage Study light theme** is mandatory.

## Primary user and constraints

- Single private owner first; an eventual multi-user release is not in v1 scope.
- New material comes from PDF documents, typed notes, plain text, and selected local files; drag-and-drop is preferred.
- Owner already studies with Bloom levels 1–2 while reading/rephrasing/writing notes, then evaluates self through mixed or ascending Bloom 3–5 questions generated by an LLM.
- Owner prefers Claude's explanation style (Sonnet by default, Opus for demanding material) and visual explanations where meaningful, and wants independent automatic retention tracking.
- No mandatory paid API usage: the owner's primary AI path is their own Claude plan through the RecallSpring connector in the Claude app (Mode A). In-app providers (ChatGPT via SIWC, Anthropic API key with a USD limit, later custom LLMs) are optional (Mode B). No local heavyweight model required.
- Desktop-first: the owner studies on one computer; phone use is deferred. RecallSpring runs locally first; the later deployment target is an existing constrained VPS running protected ProtectedApp services.

## Must-have user journeys

### J1 — Onboard and create a course
1. Sign into the private RecallSpring application (not necessarily the same identity process as SIWC).
2. Optionally connect AI: add the RecallSpring connector to Claude Desktop (Mode A) and/or connect an in-app provider (Mode B: ChatGPT via SIWC, Claude API key); show connection status, limits and consent.
3. Create a course or upload a syllabus; optional exam date and priorities.
4. Drag & drop PDF/text/Markdown; show progress and parse status; source remains preserved.
5. See proposed topic/concept map with source-linked citations; user can correct and confirm if uncertain.

### J2 — Study a new topic (learner-led)
1. Open course topic, read selected source excerpt or own notes.
2. Use an integrated notes editor and rephrase in own words; **autosave immediately**.
3. Request an explanation or a meaningful interactive visual if helpful (in the Claude app in Mode A, or in RecallSpring's tutor pane in Mode B); ordinary text stays default when clearer.
4. Request Bloom 3–5 practice, choose gradually increasing vs mixed; default recommendation based on observed performance.
5. Answer **without source hints by default**; save attempt first and model evaluation afterward.
6. Identify and correct misunderstandings; link attempts to concept and source evidence.
7. Topic enters an automatic review schedule on evidence of a completed learning attempt.

### J3 — Daily return
1. Home shows `Continue learning`, `Review knowledge`, and `Add material` plus a concise recommended plan.
2. Automatic priorities combine due reviews, weak concepts, new uncovered syllabus topics, and near-term assessment dates.
3. User can adjust available time, take a short review, pause or defer; defer is recorded and visible.
4. Each new response updates review timing and the next day's plan automatically.
5. App never claims to have updated content that has not been persisted.

### J4 — After exam
1. Exam is marked done without archiving away knowledge.
2. Key foundational concepts remain eligible for increasing-interval long-term review.
3. Optional goal `retain long term` vs `exam only` influences prioritization but never silently destroys learning history.

### J5 — Recover and control data
1. Auto-save survives interrupted model stream, browser crash, network drop, and AI quota exhaustion.
2. A queue reconciles offline notes/attempts when online; conflicting edits are identified and not silently overwritten.
3. User exports full archive (human-readable notes + structured JSON) and can restore from offsite backup.
4. Destructive changes show impact, require confirmation and remain recoverable via soft-delete for a documented interval.

## Explicit non-goals for v1

- Native ChatGPT/Claude visual or Canvas/artifact source code reuse; importing existing ChatGPT or Claude conversations.
- Scraping third-party apps or using ChatGPT/Claude.ai cookies, session tokens or consumer-plan credentials outside official flows.
- Phone-optimized flows (deferred by owner decision; keep layouts responsive where cheap).
- Full offline AI, audio-generation, camera OCR, native iOS/Android apps.
- Multi-tenant or school-wide SaaS, social leaderboards, marketplace, plugins directory.
- A standalone general-purpose AI proxy; AI integration may only power RecallSpring.
- Background AI pre-generation without separate user consent.

## Success metrics (product, not misleading learning guarantees)

- 100% acknowledged learner submissions are durable and exportable.
- 0 unapproved destructive learning-data operations.
- At least 95% of supported sources parse or yield an actionable failure state, not silent loss (measured on agreed fixtures).
- Review-to-next-action flow requires no card or date administration.
- Every model-backed assessment shows evidence provenance and uncertainty controls.
- No interruption or configuration changes to ProtectedApp as a result of development or deploy.

## Testing learning quality

Use realistic fixture courses (e.g. an introductory biology module and a programming module) and test: correct grading, concept relationships, difficulty adaptation, anti-hint behavior, and whether a returning user receives an explanation of **why** each review is due. Never rely solely on AI self-evaluation; maintain a human-reviewed gold set for regression testing.
